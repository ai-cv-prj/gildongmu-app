# 신호등 판단·표시·음성 이식 (SESAC-78·94·104·185·188·196, 2026-09-29)

`gildongmu-test-app`의 커밋 `b3e4707` ([PR #6](https://github.com/ai-cv-prj/gildongmu-test-app/pull/6))과
신호등 가림 복원 커밋 `a31ed6f`의 검출·추적·대상 선택 로직을 통합 프로젝트의 영상
파이프라인에 반영했습니다.
기존 `feature/sesac-73-traffic-tracking` 브랜치의 임시 선택·횡단보도 재확인 정책도 유지합니다.
독립 실행하며 테스트 앱 폴더나 FastAPI를 import하지 않습니다.

SESAC-104에서 테스트 앱의 신호등 음원과 안내 규칙을 저장 영상에도 반영했습니다.
추론 중 실시간 재생하지 않고, 완료된 결과 MP4의 오디오 트랙에서 들을 수 있습니다.

검출 자체가 없는 프레임을 복원하거나 점멸 상태를 인식·저장하지 않습니다.

## 대상 선택 정책

1. 신호등 하나만 보이면 즉시 임시 선택하고 색상을 분류합니다 (`single_signal`).
2. 임시 대상을 추적하는 중 여러 신호등이 보이면 색상 출력을 보류하고 횡단보도 기준으로
   후보를 다시 찾습니다. 기본 3프레임 연속 확인하면 `crosswalk_matched`로 확정합니다.
3. 같은 신호등으로 확정되면 기존 BoT-SORT ID를 유지하고, 다른 신호등이면 그 객체의 ID를
   사용합니다. 확인 중에는 `waiting_for_temporal_consistency`, 확정 시에는 `matched`입니다.
4. 횡단보도 연결을 확정한 대상은 정상 추적 중 다른 후보로 교체하지 않습니다.
   횡단보도 방향 변화나 다른 신호등의 높은 검출 신뢰도로 재선택하지 않습니다.
5. 신호등이 미검출되면 마지막 실제 검출부터 최대 3초 동안 기존 대상 ID를 보관하고
   `waiting_for_target_reacquisition` 상태로 복원을 기다립니다. 이때 과거 박스·색상은
   출력하지 않습니다. 다만 횡단보도 연결 없이 단일 신호로 임시 선택했던 대상의 ID가
   끊기고 현재 추적 가능한 신호도 하나뿐이면, 해당 신호를 새 임시 대상으로 즉시 선택합니다.
   횡단보도로 확정했거나 복수 후보 확인 중인 대상은 다른 ID로 교체하지 않습니다.
   대신 기다리는 동안에도 현재 신호등을 횡단보도 연결(신호등이 하나여도 방향 확인 필요)과
   연속 확인으로 검증하고, 모두 통과하면 3초 전이라도 새 대상으로 선택합니다(SESAC-188).
   확인 중 기존 대상이 다시 검출되면 기존 대상을 유지하고 확인 횟수를 초기화합니다.
   새로 선택한 결과의 `tracking.reselected_from_track_id`에 이전 대상 ID를 기록합니다.

임시 대상의 연결 확인을 시작한 뒤에는 횡단보도·방향이 사라지거나 하나만 검출되어도,
현재 대상의 추적이 유지되는 동안 확인 완료 전까지 색상을 보류합니다. 후보 ID가 바뀌거나
연결 근거가 끊기면 연속 확인 횟수를 초기화합니다. `association_stable_frames`는 설정 가능합니다.
트래커의 `track_buffer=30`은 프레임 수 상한이며, 별도로 촬영 시각 기준 3초 만료를 적용합니다.
신호등 박스는 작아(640 입력에서 높이 중간값 약 22px) 몇 픽셀만 움직여도 IoU가 0이 되므로,
신호등 추적의 모든 IoU 매칭은 중심을 유지한 채 박스를 2배로 키워 계산합니다(`IOU_BOX_SCALE`).
버스·장애물 추적의 IoU 계산에는 적용하지 않습니다.
소실 ID는 예측 위치와 확대 박스 IoU 0.50 이상이고 다른 행·열 후보보다 매칭 비용 차이가 0.10 이상인
명확한 경우에만 복원합니다. 낮은 신뢰도 검출은 소실 ID를 복원하지 못합니다.
영상마다 `reset()`으로 선택기와 추적기를 함께 초기화합니다. 서로 다른 영상 파이프라인의 ID는 독립적입니다.

## 기준과 반환 형식

- 신규 신호등 기본 검출 신뢰도 0.25, YOLO 입력 크기 640, 색상 분류 기준 0.60.
  휴대폰 전송 프레임(긴 변 640px)과 같은 크기이며, 640으로 학습한 검출기를 사용합니다(SESAC-185).
- 저신뢰 연결 하한은 `min(0.1, traffic.conf)`이며, 신호등 신규·고신뢰 기준은 `traffic.conf`입니다.
- 횡단보도의 독립 설정은 유지합니다. 표시 하한은 `min(traffic.conf, crosswalk_min_confidence)`,
  연결 하한은 `crosswalk_min_confidence`(기본 0.50)입니다.
  YOLO 호출은 복구용 하한까지 낮추되 횡단보도는 원래 표시·연결 기준으로 다시 걸러냅니다.
- 횡단보도 위치: 아래쪽 ≥ 높이 55%, 중심의 가로 편차 ≤ 너비 30%.
- 연속 연결 확인: 신호등 ID 동일 + 이동 보정한 횡단보도 IoU ≥ 0.30, 기본 3프레임.
- 프레임 번호 불연속·시각 역순·1초 초과 간격·해상도 변경이면 선택·추적 이력을 초기화합니다.
- BoT-SORT: match_thresh 0.8, track_buffer 30, fuse_score 미사용, ReID 비활성.

`TrafficSignalPipeline.predict(frame, frame_id=..., captured_at_ms=...)` 반환 형식:

| 필드 | 의미 |
| --- | --- |
| `detections` | 중복·미연결 저신뢰 검출 제거 후 신호등. 픽셀 `xyxy`, `confidence`, `selection_status`, `signal_state`, `color_confidence`, `track_id` |
| `crosswalks` | 내부 판단·진단용 횡단보도. 픽셀 `xyxy`, 신뢰도, `crosswalk_status`, `exclusion_reasons` |
| `selected_detection_index` / `candidate_detection_index` | 현재 `detections`의 선택/확인 중 인덱스. 객체 ID와 다름 |
| `detected_signal_count` | 필터 적용 후 표시·선택에 사용하는 신호등 수 |
| `raw_detected_signal_count` | 중복 제거·추적 연결 필터 적용 전 신호등 검출 수 |
| `suppressed_signal_count` | 중복으로 제거한 신호등 수 |
| `unmatched_low_confidence_count` | 중복 제거 후 기존 객체와 연결되지 않아 제외한 낮은 신뢰도 신호등 수 |
| `detected_crosswalk_count` / `crosswalk_candidate_count` | 연결 기준 통과 수 / 횡단보도 후보 수 |
| `crosswalk_diagnostics` | 검출·연결 상태, 기준 통과 수, 후보 목록의 `selected_crosswalk_index` |
| `association` | 선택 사유, 추적 번호, `tracking.tracker=botsort`, 횡단보도용 `tracking.camera_motion`, `selection_origin` |

`association.crosswalk_index`는 연결 기준 통과 목록의 인덱스입니다.
진단 목록의 연결 박스는 `crosswalk_diagnostics.selected_crosswalk_index` 또는 `crosswalk_status=used`로 찾습니다.
확인 중에는 최종 선택 인덱스·색상 신뢰도가 null이고 최종 색상은 unknown입니다.
영상마다 ID가 다시 시작하므로 서로 다른 영상의 같은 번호는 동일 객체를 의미하지 않습니다.

OpenCV 결과 영상은 영문 라벨을 사용합니다. TARGET·CANDIDATE·UNSELECTED 모두 객체 ID를 표시하고,
검출 신뢰도(det)와 색상 신뢰도(color)를 구분합니다. 테스트 앱처럼 횡단보도 박스·라벨,
소실점·연결선과 하단 횡단보도 진단 패널은 표시하지 않습니다. 횡단보도 검출·연결 판단과
반환 진단 데이터는 유지하며, 도보 모듈의 핑크색 횡단보도 마스크도 그대로 표시합니다.

## 모델·의존성·실행

`configs/paths.yaml`의 기본 경로는 640으로 학습한 `weights/traffic/best_YOLO_640.pt`입니다(SESAC-185).
이전 검출기 `best_YOLO_v2.pt`는 960 학습 모델이며 테스트 앱의 같은 이름 파일과 SHA-256이 같습니다.
색상 분류기는 테스트 앱과 동일합니다.
가중치는 Git 제외 대상이므로 다른 환경에는 별도로 배치해야 합니다.
현재 보행·장애물 가중치 배치는 `configs/paths.yaml`을 따릅니다.

- 검출기 SHA-256 (`best_YOLO_640.pt`): `caabaccf5f5a5f67813caa4abca6fba99a9adc3ecb61b9ec306db9ce2cc3cdc7`
- 이전 검출기 SHA-256 (`best_YOLO_v2.pt`): `d530a19b53570988ded114defdbd77af51d0ad06228cad38b7464c9758da42aa`
- 분류기 SHA-256: `e3fb14c1efd89686be7f03fba98f5aac34c57430436d1e1415fc448f25745098`

객체 매칭 의존성 `lap==0.5.13`을 `requirements.txt`에 추가했습니다.
신호등 모드에서만 추적 의존성을 불러오며, 실행 도중 자동 설치하지 않습니다.

```bash
python -m pip install lap==0.5.13
python -m scripts.run_video_inference --sample-dir data/samples/input/sample3
python -m scripts.run_video_inference --mode traffic --sample-dir data/samples/input/sample3 \
  --output-dir data/samples/output/traffic
python -m pytest -q
```

기본 모드는 `all`입니다. `both`는 도보·장애물, `traffic`은 신호등 단독 추론입니다.
예시 입력의 출력은 `data/samples/output/sample3/result_원본파일명.mp4`이며,
신호등 단독 비교 영상은 `data/samples/output/traffic/sample3/`에 따로 저장합니다.
위험 로그를 켜면 같은 폴더에 `.risk.jsonl`도 저장합니다. 폴더가 없으면 생성하고,
같은 이름의 결과가 있으면 추론 완료 후 교체합니다. 공용 `--conf`, `--imgsz`는
장애물 검출용이며 신호등 설정은 YAML의 `traffic` 항목을 사용합니다.

## 검증 결과

### SESAC-196 정면 횡단보도 방향 보조 규칙 (2026-10-08)

신호등이 여러 개면 횡단보도 줄무늬의 잘리지 않은 양쪽 끝점으로 가장자리 선을 그려 건너는 방향을 찾습니다.
넓은 횡단보도를 정면 가운데에서 보면 가까운 줄무늬 끝이 화면 좌우로 잘려 끝점이 부족하고,
방향을 찾지 못해(`vanishing_point_unavailable`) 대상 신호등을 고르지 못했습니다.

| 10/08 같은 장소 | 오전 | 오후 |
| --- | --- | --- |
| 촬영 위치 | 보도 연석 앞, 약간 비스듬히 | 횡단보도 정면 가운데 |
| 좌우 끝이 모두 잘린 줄무늬 | 0% | 40% |
| 방향 추정 성공 | 72% | 16% |

끝점 방식 자체가 정면 장면에 약해 test-app 조건(960 입력·v2·960 고정값)에서도 같은 오후 녹화의
2개 이상 선택률은 35.3%였고, 640 입력에서는 작은 먼 줄무늬가 더 작아져 1.0%까지 떨어졌습니다.

끝점으로 방향을 찾지 못했을 때 줄무늬가 4개 이상이고 거의 수평(기울기 중앙값 0.08 이하)이며
화면 폭의 절반 이상을 가로지르면 정면으로 건너는 것으로 보고 화면 중앙을 진행 방향으로 씁니다
(`straight_crossing_direction`). 줄무늬가 기울어 비스듬히 선 경우에는 방향을 미확정으로 남깁니다.

| 2개 이상일 때 선택 성공률 | 보조 규칙 전 | 보조 규칙 후 |
| --- | ---: | ---: |
| 오후 실기기 기록 | 0% (0/452) | 87% (252/289) |
| 오후 녹화 재실행 | 1.0% (1/98) | 59.2% (58/98) |
| 오전 녹화 재실행 | 88.6% | 89.1% |

두 방식이 모두 신호등을 고른 녹화 프레임 1,503개에서는 항상 같은 신호등을 골랐습니다.
정면 장면에서 고른 신호등이 해당 횡단보도용인지는 현장 확인이 더 필요합니다.

### SESAC-188 신호등 추적 매칭 박스 2배 확대 (2026-10-08)

10/08 녹화에서 새로 생긴 추적 ID 117개 중 64개가 3초 안에 근처에서 사라진 ID를 대신했습니다.
그중 57개는 검출이 1프레임 이상 끊긴 뒤였고, 끊긴 사이 박스가 박스 높이만큼 움직여
이전 박스와의 IoU가 대부분 0이었습니다. 원래 복원 기준(IoU 0.50)으로는 복원할 수 없었습니다.
매칭할 때만 박스를 키워 IoU를 계산하도록 바꿨습니다. 같은 녹화로 배율을 비교했습니다.

| 항목 | 1배 (이전) | 2배 (현재) | 3배 |
| --- | ---: | ---: | ---: |
| 근처 ID 대체로 보이는 새 ID | 64 | 40 | 27 |

## 저장 영상의 신호등 음성 안내 (SESAC-104)

`src/traffic_voice.py`가 프레임 시각에 따라 안내 대상을 확인합니다. 테스트 앱에서 가져온
한국어 신호 안내 MP3는 `configs/paths.yaml`의 `voice_dir`에 있으며,
`src/video_audio.py`가 이 설정을 읽어 결과 MP4에 합성합니다.
시작 안내 없이 첫 프레임부터 신호를 확인합니다. 선택된 신호등의 정수 `track_id`와
빨강·초록 색상이 필요합니다.

- 같은 대상·같은 색을 3프레임·400ms 이상 확인 후 안내.
- 최초 초록불은 “초록불입니다. 다음 초록 신호를 기다려 주세요.”.
- 같은 대상의 연속 빨강↔초록 전환 시 변경 안내, 같은 색은 즉시 반복하지 않음.
- 신호색 확인 이력이 있을 때만 2초 이상 확인 불가 구간에서 한 번 안내.
- 확인 불가 안내 후 재확인한 색은 같은 색이어도 한 번 안내.
- 같은 대상·같은 색이 계속 확인되면 마지막 신호 안내 후 5초(`traffic_repeat_ms`)마다 다시 안내(SESAC-196).
  첫 초록 대기 안내는 같은 문구로, 전환 안내 뒤에는 현재 색상만 읽으며, 재안내는 보행 안내를 끊지 않는 가장 낮은 신호 우선순위를 사용.
- 재확인 초록불은 “초록불입니다.”. 상위 경고가 재생 중이면 지난 신호 안내는 대기시키지 않고 폐기.

후속 횡단보도 이탈 안내에서 신호등과 도보 장애물 음성을 단일 트랙으로 통합했습니다.
우선순위는 횡단보도 이탈 → 장애물 위험 → 신호 변경 → 일반 신호이며, 상위 안내와 겹친 하위 안내는
폐기합니다. 브라우저도 같은 우선순위를 전역 음성 관리자 한 개로 적용하고, 음성은 영상 길이에서 끝납니다.

자동 테스트는 전체 191개가 통과했고, 실제 가중치를 사용한 `all` 모드 2프레임 영상에서
MP4 오디오 트랙 생성을 확인했습니다. 이 짧은 확인으로 sample3의 신호색 안내 정확도를
검증한 것은 아닙니다.

통합 영상은 원본 FPS와 영상 시각을 사용하며, 테스트 앱은 초당 최대 5회 처리합니다.
횡단보도 연결의 3프레임 조건은 5FPS에서 약 0.4초, 30FPS에서 약 0.067초입니다.
횡단보도 대상 선택 조건에는 별도의 최소 400ms 검사가 없으며, 위 음성 확정 조건과 구분합니다.
직접 `predict(frame)`만 호출하면 호환용 연속 번호·200ms 간격을 사용하므로 실제 입력에서는
명시적인 촬영 시각을 전달해야 합니다.
